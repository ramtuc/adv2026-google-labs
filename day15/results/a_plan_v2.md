# 和菓子屋「ゆきみ堂」店番ゲーム 実装計画

和菓子屋「ゆきみ堂」の店番をして注文の品揃えとレジのおつり渡しを行うブラウザゲームを、外部ライブラリ・CDNを使わずにバニラ HTML / CSS / JavaScript（ES Modules）で作成します。

## 設計のポイント・前提事項

> [!NOTE]
> **判定と画面遷移のフローについて**
> - **ステップ1（品揃え →「お会計」ボタン押下）**：棚から品物と個数を選び「お会計」を押すと、お客が払うお金（例：千円札 1 枚）が提示されます。
> - **ステップ2（おつり渡し → 結果表示）**：**会計画面には「税込合計金額」や「おつりの額」は一切表示しません**。プレイヤー自身が、お品書きの税抜価格・箱代ルール・税率（持ち帰り8% / 店内10%）・お客の出したお金から頭の中で（あるいは暗算・メモで）計算し、お札と硬貨の枚数を選んでおつりを渡します。
> - **おつりを渡したあとの結果表示**：おつりを渡して確定した後の正誤フィードバック画面で初めて、**正しい税込合計金額・箱代の有無・正しいおつりの額（およびプレイヤーが渡した額）**を表示します。
> - **税込計算の浮動小数点対策**：`Math.floor((subtotal + boxFee) * 1.08)` は JavaScript の浮動小数点誤差（例：`2500 * 1.08` 等）が生じる場合があるため、`Math.floor((subtotal + boxFee) * ratePercent / 100)`（`ratePercent` は `108` または `110`）の整数演算で厳密に切り捨てます。
> - **ES Modules (`type="module"`) の動作**：`logic.js` を `export` し `app.js` から `import` するため、ブラウザ検証時はローカル HTTP サーバー経由で起動します。

## Proposed Changes

### 1. ロジック層（`logic.js`）

画面（DOM）から完全に切り離された純粋関数群と定数を定義し、`export` します。

#### [NEW] [logic.js](file:///e:/tmp/yukimido_a/logic.js)

- **定数・お品書き定義 (`MENU_ITEMS`, `DENOMINATIONS`, `BOX_FEE_PRICE`)**
  - 各品目に `id`, `name`, `shortName`（注文セリフ用：「雪うさぎ（上生菓子）」はセリフで「雪うさぎ」とも呼べるよう対応、表示名も保持）, `price`（税抜）, `dineInOnly`（店内のみフラグ）を持たせます。
  - 金種配列 `DENOMINATIONS = [10000, 5000, 1000, 500, 100, 50, 10, 5, 1]`。
- **`calculateBoxFee(items, orderType)`**
  - `orderType === 'takeout'` かつ `items['yukiusagi'] >= 5` のとき `150`、それ以外は `0` を返す。
- **`calculateSubtotal(items)`**
  - 選択された品物マップ `{ [itemId]: count }` から税抜の品物合計金額を計算して返す。
- **`calculateTaxIncludedTotal(items, orderType)`**
  - 品物合計 `subtotal` と箱代 `boxFee` を足し、`orderType === 'takeout'` なら `8%`（`× 108 / 100`）、`'dine_in'` なら `10%`（`× 110 / 100`）を掛けて `Math.floor` で円未満を切り捨てた税込合計を返す。
- **`isOrderCorrect(expectedOrderItems, selectedItems)`**
  - お客の注文 `{ [itemId]: count }` とプレイヤーが棚から選んだ `{ [itemId]: count }`（0個のキーは無視）が完全に一致するかを boolean で返す。
- **`calculateMinCoins(amount)`**
  - おつり金額 `amount`（0以上の整数）に対し、日本の通貨（`[10000, 5000, 1000, 500, 100, 50, 10, 5, 1]`）で表現できる最少枚数の内訳 `{ [denom]: count }` と合計枚数 `totalCount` を返す。
- **`evaluateTransaction({ expectedOrderItems, selectedItems, orderType, paidAmount, changeCoins })`**
  - 注文が正しいか（`orderCorrect`）、渡したおつり金額が（注文本来の税込合計に対するおつり、かつ選択品に対するおつりとして）正しいか（`changeCorrect`）、全体の成否（`isSuccess = orderCorrect && changeCorrect`）、最少枚数と一致しているか（`isOptimalChange`：手ぎわ点 +1 対象）をまとめて判定して返す。
- **`generateCustomerOrder(rng)` / `generatePayment(totalAmount, rng)`**
  - 決まり1・5・7に従い、1〜3種類・各1〜6個の注文（持ち帰りの場合は店内専用品を除く）と、税込合計以上のお客の支払い金額＋金種内訳を生成する関数。

### 2. 画面構造・スタイル・ゲーム進行（`index.html`, `style.css`, `app.js`）

- **お客エリア**：お客のアイコン・吹き出し（注文内容と「持ち帰りで」「店内で食べていきます」の明示）、結果フィードバック表示。

  3. **おつりを渡した後の結果表示**：
     - 正誤判定（「ありがとうございました！」または「ちがうよ…」）とともに、**正しい税込合計金額（品物合計・箱代・税率の内訳）**と**正しいおつりの額**（およびプレイヤーが渡した額・手ぎわ点獲得の有無）を表示して次のお客へ進む。

  - 1日の売上、来たお客の数、正解したお客の数、手ぎわ点、最高売上の更新通知、「もう1日店番をする」ボタン。

## Verification Plan

### Automated Tests
- Node.js を用いて `logic.js` の単体検証をサンドボックス内で実行します：
  - 持ち帰り（8%）と店内（10%）の税込計算と端数切り捨ての正確性
  - 雪うさぎ5個以上×持ち帰りのときのみ箱代150円（税抜）が加算され、店内や4個以下では加算されないこと
  - 持ち帰りのお客が「白玉ぜんざい」「季節の上生菓子と抹茶」を注文しないこと、品数が1〜3種類・各1〜6個であること
  - 最少枚数のおつり計算と「手ぎわ」判定の正確性

### Browser Verification
- ローカル HTTP サーバーを起動し、`browser` サブエージェントで実際にゲームをプレイして以下を検証します：
  1. ゲーム開始から客の注文表示、棚からの品物選択、「お会計」でお客の支払い金額が表示されること。
  2. 正しい品物と最少枚数のおつりを渡したときに売上が加算され、「手ぎわ」点が1点増えること。
  3. わざと最小枚数ではない同じ金額のおつり（例：100円玉1枚の代わりに50円玉2枚など）を渡したとき、売上は増えるが手ぎわ点は増えないこと。
  4. わざと間違えた注文またはおつりを渡したとき、お客が帰り売上が増えないこと。
  5. 90秒終了時（またはタイマー完了時）に売上・来店客数・正解数・最高売上が表示され、`localStorage` に保存されること。
