    - line 289: `log must warn ドアの状態が変わった（開 → 閉）`

## 2. 考えられる原因
- `git diff HEAD -- main test` の結果、`main/main.c` の `last_door` 変数の宣言から `RTC_DATA_ATTR` 属性が削除されていました。
- 差分内容:
  ```diff
  --- a/day14/door_sensor/main/main.c
  +++ b/day14/door_sensor/main/main.c
  @@ -37,7 +37,7 @@ _Static_assert(DOOR_WAKEUP_TIMER == ESP_SLEEP_WAKEUP_TIMER, "TIMER enum mismatch
   _Static_assert(DOOR_WAKEUP_TOUCHPAD == ESP_SLEEP_WAKEUP_TOUCHPAD, "TOUCHPAD enum mismatch");
   
   RTC_DATA_ATTR static uint32_t boot_count = 0;
  -RTC_DATA_ATTR static int last_door = -1;
  +static int last_door = -1;
   
   static int read_battery_mv(void)
   {
  ```
- **ドアセンサーの動作への影響**:
  - ESP32-S3 では、ディープスリープ（Deep Sleep）中に通常の SRAM への電源供給が遮断されるため、`RTC_DATA_ATTR`（RTC 低速メモリ領域への配置指示）が付いていない変数の値はスリープ復帰時に保持されず、初期値（`-1`）にリセットされます。
  - これにより、ディープスリープ復帰時に前回のドア状態（`last_door`）が失われて毎回 `-1`（未確定）となり、ドア状態の変化（例：開 → 閉 や 閉 → 開 への遷移）を検知できなくなります。
  - 結果として、状態変化時の警告ログ出力（「ドアの状態が変わった（開 → 閉）」等）や状態変化に応じた通知機能が動作しなくなります。

## 3. 直し方の提案
- `main/main.c` の 40 行目付近にある `last_door` の宣言に `RTC_DATA_ATTR` 属性を復元してください。
  ```c
  RTC_DATA_ATTR static int last_door = -1;
  ```
- 修正後、`powershell -NoProfile -File test/run_host_tests.ps1` を実行し、全6テスト（63アサーション）が PASS することを確認してください。
